7.3 Descripción de objetos y características de estudio

En el contexto de este proyecto, el objeto de estudio es la prenda de vestir representada en una imagen digital (fotografía de catálogo o imagen de consulta subida por el usuario). Cada registro del experimento se asocia a una imagen y, cuando aplica, a su etiqueta de referencia (categoría, color dominante, etc.) en el archivo de metadatos.

Las características de estudio son los atributos que el sistema debe extraer, comparar o usar para el matching con el catálogo. Según el enfoque del prototipo, pueden incluir:

  • Características de color: representación en espacio HSV mediante histogramas (por ejemplo, 16 bins por canal), normalizados para comparación entre imágenes.
  • Características de forma: contornos, momentos espaciales y momentos invariantes de Hu, útiles para distinguir siluetas de prendas.
  • Atributos semánticos (si se usa modelo de visión por API): tipo de prenda, color principal y secundario, patrón o estilo, según el esquema JSON acordado con el catálogo.

La relación entre objetos y características permite evaluar objetivamente la hipótesis del proyecto (por ejemplo, precisión de categoría ≥ 85% en dataset controlado) y justificar el diseño del pipeline de procesamiento.

Ambiente controlado

Se denomina ambiente controlado al conjunto de condiciones fijas que garantizan que las mediciones (precisión, tiempos, estabilidad del JSON o de los descriptores) sean comparables entre corridas y versiones del sistema.

Dataset de evaluación (condiciones estrictas): imágenes de prendas sobre fondo blanco o gris claro uniforme, sin maniquí; iluminación difusa y frontal; resolución mínima acordada (por ejemplo, 512×512 px); formato JPG o PNG con compresión no destructiva. Cada imagen se identifica y documenta en un CSV de metadatos (ground truth).

Imagen de consulta en uso real (condiciones amplias): el sistema puede aceptar fotos con variaciones de fondo, varias prendas u outfit completo; en ese caso el modelo de visión debe segmentar semánticamente las prendas. Las métricas de evaluación reportadas en el informe deben indicar si corresponden al dataset controlado, a consultas reales o a ambos.

Ambiente de ejecución: versión de Python, de OpenCV y del sistema operativo; o, si se usa API, modelo y parámetros de configuración documentados, para reproducibilidad.

Matriz de características (con el objeto y normalizada)

La matriz de características organiza los datos numéricos del experimento: cada fila corresponde a un objeto (una imagen del dataset o una consulta); cada columna corresponde a un componente del vector de características.

Por ejemplo, si el vector concatena histograma HSV (16+16+16 valores) y siete momentos de Hu, cada fila tendrá dimensiones 1 × d, con d = 55. En notación matricial, si hay n imágenes, la matriz X ∈ ℝn×d concentra todas las muestras para comparación y evaluación.

La normalización es necesaria para que magnitudes distintas (por ejemplo, bins de histograma frente a momentos) no dominen la distancia entre vectores. Típicamente se normaliza el histograma a suma 1 (o se usa la norma L1/L2 del vector completo según el criterio del equipo). Los valores normalizados se documentan en el informe para permitir reproducir el experimento.

Etapas de la visión artificial y características desarrolladas en cada etapa

El procesamiento se descompone en etapas secuenciales. En cada una se indica la técnica empleada y las características que aporta al sistema.

Etapa Descripción Características / salida
1. Adquisición Carga y validación de la imagen (formato, tamaño, resolución mínima). Imagen en memoria lista para procesamiento; metadatos de entrada.
2. Preprocesamiento Redimensionado, conversión de espacio de color, reducción de ruido. Imagen normalizada para tiempos estables y comparación justa.
3. Segmentación Aislamiento de la prenda (GrabCut, umbralización adaptativa, etc.). Máscara o región de interés; reducción de influencia del fondo.
4. Extracción de características Histogramas HSV, momentos de Hu, contornos / bordes si aplica. Vector de características numérico por imagen.
5. Comparación y decisión Distancia entre vectores (euclidiana, Chi-cuadrado); ranking Top-K. Ítems similares del catálogo; clasificación de categoría; métricas Precision@K / Recall@K.

Nota: Si el prototipo delega la interpretación en una API de visión, las etapas 3–4 se sustituyen por inferencia del modelo (detección de prendas y atributos en JSON); las etapas de adquisición y preprocesamiento siguen siendo necesarias para homogeneizar la entrada.

Base de conocimiento

La base de conocimiento del proyecto es el conjunto estructurado de material visual y metadatos que permite entrenar, configurar y evaluar el buscador visual.

  • Muestras de imagen: fotografías de catálogo (fondo neutro) alineadas con las categorías del proyecto (por ejemplo, playeras, pantalones, sudaderas, calzado), con nomenclatura y CSV de etiquetas.
  • Video (opcional): material complementario para demostración o documentación del flujo (por ejemplo, captura de pantalla del prototipo o secuencia de consultas); no es obligatorio para el núcleo PDI si la asignatura no lo exige.
  • Redacción de características de estudio: para cada imagen (o clip), documentación escrita de categoría, colores, y criterios de similitud esperada, de forma que el equipo y el evaluador sepan qué respuesta es correcta.
  • Muestras positivas: pares consulta–ítem del catálogo donde la coincidencia es la esperada según metadatos; sirven para medir aciertos.
  • Muestras negativas: casos donde el sistema no debe confundir categorías o colores (por ejemplo, prenda oscura vs. clara, o categorías límite); sirven para analizar errores y robustez.

Desarrollo del algoritmo principal e hiperparámetros

El algoritmo principal del prototipo es el que, a partir de la imagen de entrada, produce el ranking de prendas similares y/o la clasificación de categoría. En el enfoque basado en OpenCV, el núcleo suele combinar segmentación, extracción de histograma y momentos, y cálculo de distancia entre vectores.

Los hiperparámetros son valores fijados antes de la evaluación (no aprendidos automáticamente en este proyecto). Ejemplos típicos:

  • Tamaño de redimensionado (por ejemplo, 256×256 px) y σ del filtro Gaussiano.
  • Número de bins por canal HSV (por ejemplo, 16) y tipo de normalización del histograma.
  • Parámetros de GrabCut (iteraciones, rectángulo inicial) o de umbralización adaptativa.
  • Umbrales de Canny o tamaño de kernel morfológico, si se usan en la segmentación.
  • Tipo de distancia (euclidiana vs. Chi-cuadrado) y valor de K en Top-K.

Si se utiliza un modelo de visión externo (API), se documentan como “hiperparámetros operativos”: identificador del modelo, límites de tokens, temperatura o equivalentes, y versión del prompt estructurado. En el informe se describe el procedimiento de ajuste: cómo se eligieron los valores (prueba por validación en el dataset controlado, criterio de tiempo máximo de respuesta, etc.).
